# Bench scripts

Hardware test scripts for snd-clarett, run against a live unit. Each appends to a log named after
itself in the current directory (or in `$BENCH_LOG_DIR`), so run them from a scratch directory.
Most need root (dynamic debug, sysfs binds, fcp-server control); the user is prompted wherever a
hand on the unit is needed. `sudo` resets the environment, so pass the log directory through it
(`sudo BENCH_LOG_DIR=~/clarett-bench bash ...`) or the log lands in the current directory owned by
root. `<card>` is the ALSA card number, `<bdf>` the unit's PCI address
(`cat /proc/asound/cards`, `lspci -d 1cb5:`).

| script | what it checks |
|---|---|
| `attach_test.sh [N]` | Cold attach over N power cycles: response-address acknowledgement time, which attempt answered, enable -> registered, Thunderbolt appearances. |
| `rebind_test.sh <bdf> [N]` | The same over N warm sysfs unbind/bind cycles. |
| `phase_check.sh <card> <bdf>` | Mailbox phase bits per command (3 s trace), then a 25 s capture while the monitor knob is turned (events relayed mid-stream) and one hands-off (none relayed). |
| `notify_reads.sh <card> <bdf> [seconds]` | Mailbox cost of front-panel notifications: over a window (default 15 s) while a control is turned, the relays by event word and every FCP command by opcode, with GET_DATA per second and the md5 of the running fcp-server. Relays are counted before the driver's 50 ms debounce, so compare GET_DATA per second between builds. Root. |
| `idle_write.sh <card> <bdf> [idle_s] [control]` | No host traffic for minutes (GUI closed), then a switch write through fcp-server; asks whether the front panel followed. |
| `arm_cost.sh <card> <bdf> [label] [N]` | Mailbox commands and time from stream open to engine armed, plus simultaneous capture + playback starts. Logs the module srcversion, for before/after comparisons. |
| `svc_cpu_ab.sh <card id> <a.ko> <b.ko> [secs] [periods...]` | A/B of the stream servicer's CPU cost between two builds of the module on ONE host and unit, which is the only basis for comparing them: reloads each in turn and times the `clarett-svc` thread (`/proc/<tid>/stat`) across a capture at each ALSA period size (default 512 and 64). Looks the card up by id, since a reload can hand it another number, and takes the capture width from the card. Stops fcp-server and alsa-state to free it and refuses to run if anything else still holds it (rather than killing it, which could take out PipeWire); leaves the module named last loaded. Reloads with the unit powered on, as the rebind tests do — no power cycle, so the Thunderbolt reconnect race is not in play. Root. One unit at a time. |
| `cause_probe.sh <card> <bdf> [secs]` | What the `0x100` summary register shows, and whether its two enabled-but-never-observed bits (4 and 5) are stream error indicators: a plain capture, then a 16-frame period (the cadence at which the DEVICE flags period overruns), then the same in duplex (the only way to make the playback block do anything). Per leg it reports the device overrun count, the OR of every `0x100` value the servicer read (`cause=`) and any `stream-cause:` line, which the driver emits once per stream when a bit outside `IRQ0_CAUSE_KNOWN` appears. No vendor capture of any model contains a single overrun, so this is the gap those traces cannot close. Root (dynamic debug). |
| `irq_rate.sh <card> <bdf> [secs]` | Which MSI vector the data plane's period events arrive on: each vector's interrupt count over an idle window, then over a capture at each of two ALSA period sizes (`PERIODS="512 64"`), against the period events the driver counted. A vector carrying them reads ~1.000 per event at both sizes; a fixed-rate source does not. Stops that card's fcp-server meanwhile (`KEEP_FCP=1` to leave it), so vec0's mailbox traffic is not in the way. Root for the `periods=` figure; without it the expected cadence (rate/period) is used instead. |
| `stream_info.sh <card>` | Raw STREAM_INFO replies for bands 0-3 via `tools/fcp_cmd.c` (stops fcp-server meanwhile). |
| `names_probe.sh <card>` | FCP category 5: every `0x005000` id from 0 to 0x100 (64-byte replies), eight request shapes, high ids and three reply lengths, with the driver's `FCPr` trace on so each reply's true size and status are logged. Sends only `0x005000`. Stops that card's fcp-server meanwhile. Root; needs `fcp_cmd`. `names_sum.py <log>` pairs each request with its reply. |
| `cat7_probe.sh <card>` | FCP category 7 (`0x007000`-`0x007003` only, the vendor's opcodes): request shapes idle, then STREAM_INFO, `0x007000` and both channel lists after and during a capture at each rate 44.1-192 kHz, with the `FCPr` trace on. Takes the card from PipeWire (profile off, restored) and stops fcp-server meanwhile. Root; needs `fcp_cmd`. `cat7_sum.py <log>` lists each reply trimmed to its true size; `cat7_recs.py <cat7 sum> <names sum>` decodes the channel records into named runs. |
| `cat7_offset.sh <card>` | The channel-list request's `first` field: `0x007002`/`0x007003` with bytes 2-3 (a starting index) and the count varied, per band, with the `FCPr` trace on. Stops that card's fcp-server meanwhile. Root; needs `fcp_cmd`. Summarise with `cat7_sum.py`. |
| `midi8_probe.sh <card> [0x008001\|0x008002] [all\|empty]` | FCP category 8 port lists: `0x008001` (MIDI inputs) or `0x008002` (outputs), every request shape or only the empty one, with MIDI_INFO (`0x008000`) read before and after as a check, and the `FCPr` trace on. Refuses any other opcode. Stops that card's fcp-server meanwhile. Root; needs `fcp_cmd`. |
| `loopback_order.sh <card>` | Digital-loopback ramp at 48/96/192 kHz on any Clarett or a Red 8Line/4Pre (model from the card id; the Red gets per-rate legs): capture channel order (loopback and ADAT 1), sample-exactness, S/MUX-removed channels silent. Whatever the ramp channel feeds is switched off for the run and restored; `RAMP=<n>` picks another playback channel. Run as your user. |
| `duplex_stress.sh <card>` | Simultaneous capture + playback, checked with a streamed loopback ramp: long legs at 48/96/192 kHz and a 64/256 leg, then N cycles started and stopped in the same instant at mixed rates (no servicer thread or stuck client may survive), then a playback opened at another rate mid-capture. `P64=1` runs only the low-latency regression instead (a 1.33 ms period at 48/96/192 kHz, 60 s each). PipeWire's profile and the routes it touches are restored at exit. `SHORT=1` for a ~3 min run. Run as your user, and do not start alsa-scarlett-gui during it (it clears mono routes from linked pairs at startup). |
| `duplex_ramp.py` | Streaming ramp generator and live checker used by the duplex and tx_guard scripts (`count` mode separates torn frames from silent gaps). |
| `tx_guard_lead.sh <card> [reps] [secs]` | The `tx_guard` question: a short-lead playback client (`leadplay`) and aplay, at periods 32 and 64, at guards 16/32/64, through the loopback ramp; counts breaks (torn/misplaced frames) apart from gaps (frames lost as silence). `tx_guard` is a constant on a current driver, so the sweep collapses to the compiled-in guard (reported as `builtin`) and no sudo is needed; where the parameter still exists it is swept and restored at exit. **This is also the test for any change to the servicer's cadence**: a short-lead client is the only one that notices how often playback is topped up, and the ramps cannot see it. Run as your user; needs `leadplay` built at `$BENCH_LOG_DIR/leadplay`. |
| `rt_latency.sh <card> [legs]` | Analogue round-trip latency through a cable from Analogue Output 1 to Analogue input 1 (`OUT=n` for another pair): per leg (`rate:period`, buffer 4 periods) the frames from a click written to playback until it is captured, analogue and on a digital-loopback reference. Sets the output to software volume at 0 dB and routes it straight from playback for the run; everything restored at exit. Run as your user; needs `rtlat` built at `$BENCH_LOG_DIR/rtlat`. A leg right after a rate change misses its first clicks (the analogue input is muted ~1 s while the converters re-lock). `DIGITAL=1` (the default on a Red) needs no cable: both of rtlat's pairs use the digital loopback, which measures the device latency (32 frames since snd-clarett `6ab6f87`). On a Red, `DIGITAL=0` measures the analogue path: Analogue Output `OUT` (Monitor L/R = 1/2, Line Output 1 = 7) routed straight from playback, capture from input `IN` (default `OUT`), output level and input mode left as set. `IN=` names a different input on the Claretts too. |
| `rtlat.c` | Linked-duplex click timer used by the latency script. `gcc -O2 -o rtlat rtlat.c -lasound -lm`. |
| `leadplay.c` | Playback client that holds a fixed short queue ahead of the hardware, playing the ramp; used by the tx_guard script. `gcc -O2 -o leadplay leadplay.c -lasound`. |
| `live_cap.sh <card>` | Live capture position: a client (`livecap`) asking the driver for its position every 250 us and reading whatever is there must still get the loopback ramp sample-exact at 48/96/192 kHz (per-model legs; `LEGS="rate:period ..."` overrides). Each leg logs how many reads were shorter than a period (many, down to 16 frames, on a driver with a live position; none on one without). A leg whose livecap reports xruns broke by recovering from a host stall: read it against `gapmax`. The ramp is generated to a file before each leg (fed live through a pipe, aplay underran at the short 192 kHz legs) and aplay's underruns are logged. Run as your user; needs `livecap` built at `$BENCH_LOG_DIR/livecap`. |
| `livecap.c` | Capture client for the live-position test: non-blocking, `snd_pcm_avail()` (which asks the driver; `snd_pcm_avail_update()` does not) every 250 us. `gcc -O2 -o livecap livecap.c -lasound`. |
| `load_build.sh <ko\|installed> [card id]` | Swaps the loaded snd-clarett for another build: takes the Clarett cards from PipeWire (profile off, as your user), stops fcp-server and alsa-state, reloads, switches the `stream-svc` telemetry on (`DYNDBG=0` leaves it off) and waits for the card's routing controls. Leaves PipeWire's profile off. Run as your user (asks for sudo). |
| `lead_ab.sh <card id> <A.ko> <B.ko> [reps] [secs]` | Short-lead playback A/B between two builds: the `tx_guard_lead.sh` cell "leadplay period 32" in blocks A B A B, with a count per rep of the servicer windows that had a gap of 40 ms or more, so a host stall can be told from the driver. Leaves the card on B. Run as your user (asks for sudo); needs `leadplay`. |
| `start_stall_ab.sh <card id> <A.ko> <B.ko> [blocks] [streams]` | Stalls at stream start, A/B: blocks alternating A B A B (default 6 x 12), each a run of 4 s duplex ramp streams rotating 48/96/192 kHz; per stream the ramp check, the first window's `gapmax`/`readmax` (and `posmax`, on a build that times the ring-position read), the worst gap, and aplay underruns. Run as your user (asks for sudo). |
| `clock_live.sh <card> [external]` | Clock Source changed while streaming: a 20 s loopback ramp with the source switched to an absent external one and back, Sync Status after each switch, the ramp's breaks; then the same switches with PipeWire holding the card. Run as your user. |
| `sleep_test.sh <card|none> [s2idle|deep|hibernate] [secs]` | System sleep and resume (default deep, 20 s) through `systemctl suspend` (`systemctl hibernate` for `hibernate`, which needs a disk swap and `resume=`), so systemd's sleep hooks (NVIDIA's on a hybrid-graphics laptop) run, woken by an RTC alarm. With a card: stream states, Sync Status and fcp-server before and after, a Level Meter read to prove the mailbox answers, whether the device resumed in place or was re-enumerated, and the snd_clarett/thunderbolt/fcp-server log across the sleep. `none` is the baseline with nothing attached. Root. |
| `vm_red.sh attach\|detach [card-id] [domain]` | Hot-plugs a unit (default card id `R8Line`; a Clarett by its card id, e.g. `C8PreX`) into a RUNNING libvirt VM (the `domain` argument, else `$VM_DOMAIN`) and takes it back, live only: Windows does not boot with a Red 8Line attached but takes it once up. Looks up the unit's PCI address each time (it changes on a replug), refuses while fcp-server or anything else holds the card, and lets libvirt (`managed='yes'`) swap snd_clarett and vfio-pci. Attach after Windows is up, detach before it shuts down. No root (needs `qemu:///system` access). |
| `sync_latch.sh <card> [external]` | SYNC_READ (0x006004) bit 1: after each Clock Source change, the word read once after 2 s unread and once polled every ~30 ms for 300 ms, with a no-change control (default external source S/PDIF, which should have nothing connected). Root; builds `tools/fcp_sync_read.c` itself, stops that card's fcp-server meanwhile and restores it and the Clock Source at exit. |
| `flash_latency.sh <card id or number> [N] [segment] [len]` | Times N back-to-back `FLASH_READ`s (default 200 x 64 B of segment 4, `App_Env`) through the driver: min/median/p90/p99/max per read, how many exceeded the normal 100 ms response deadline, failures. Stops that card's fcp-server meanwhile. Root; needs `fcp_cmd` built at `$BENCH_LOG_DIR/fcp_cmd`. |
| `unit_ident.sh <card id or number>` | Read-only identity snapshot: appspace bytes 0-127 (App version @8, FPGA word @12, FPGA type @16, the saved nickname), the `0x800005` {family, model} reply, and the first 32 bytes of flash `App_Env` (the serial) and `FPGA_Upgrade` (the bitstream's design name). Stops that card's fcp-server meanwhile. Root; needs `tools/fcp_cmd.c` built at `$BENCH_LOG_DIR/fcp_cmd`. Its log holds serial numbers: keep it out of the repo. |
| `midi_loop.py --card <card> [--mode sysex\|notes] [--rate B/s]` | DIN MIDI self-loop (5-pin cable Out -> In): byte-exact check; in `sysex` mode the payload is a 7-bit counter, so each lost run is logged with its size and time, and the intervals between losses summarised. No root needed; nothing else may hold the rawmidi open. |
| `tb_manual_auth.sh <bolt uuid> [N] [hold_s]` | Thunderbolt reconnect race: sets the unit's boltd policy to `manual` (restored at exit), and per power cycle logs the unit's power-on link bounce, then authorizes once it has been present unbroken for hold_s and checks PCIe comes up. |
| `ramp_check.py` | Ramp generator and checker used by the loopback script. |
| `kmsg_times.py` | Attach intervals from kernel timestamps (`journalctl -k -o json \| kmsg_times.py [bdf]`), used by the attach and rebind scripts. journald's receive times batch kernel lines and are not usable for millisecond intervals. |

The digital-loopback ramp method and what each result means are described in `CLAUDE.md`.
